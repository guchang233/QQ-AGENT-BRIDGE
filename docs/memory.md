# 记忆系统

记忆插件给 Agent 一份能长期保留的笔记。设计目标是**让 AI 在该想起来的时候想起来，并且不把不该说的带出去**，不是做出最复杂的结构。

## 一条记忆包含什么

| 字段 | 说明 |
|---|---|
| `content` | 一句完整的话。提到人或话题时用 `[[小红]]` 写双链 |
| `scope` | 属于哪个会话。私聊的记忆只在那个私聊里可见，`global` 所有会话可见 |
| `subject` | 主要关于谁（QQ 号） |
| `attr` | 单值属性，如住址、称呼、工作。同一个人同一属性只保留最新值 |
| `trust` | 来源：管理员确认 / AI 观察 / 导入 / 群友自述 |
| `valid_to` | 被新事实替代的时间。旧记录保留，只是不再被取出 |

## 写入

Agent 调用 `qq_memory_remember`：

1. **合并**：和已有记忆高度相似时合并，不重复存。
2. **替代**：填了 `attr` 时，新值让旧值失效。低可信度的来源不能替代高可信度的记忆，群友改不掉管理员确认过的事实。
3. **提示**：内容相近但不确定时，把旧记忆列给 Agent，由它决定是否标记替代。这一步不额外调用 LLM。
4. **关联**：解析 `[[双链]]`，并自动连上已知的人名和别名。同一称呼对应多人时不自动连，避免连错人。

别人要求记住的内容必须带 `fromMsgId`，由服务端查消息记录确认是谁说的。群友的要求只写入他所在的会话，不进全局。「以后你要怎样」这类规则只有管理员能设定：引用的消息必须是管理员本人最近发的，内容也要能和原文对上。

## 检索

1. 先按权限过滤范围。
2. 多路召回：全文（分词 + 二元组）、人物、向量（配置后才有）、图扩散（个性化 PageRank）。
3. 用 RRF 融合排名，再按「是否回答了问题的核心词」、保持率、重要度、可信度重排，并去掉近似重复。
4. 没有相关内容就返回空，不凑数。

`qq_memory_recall` 的 `queries` 参数让 Agent 自己补同义说法。这是不配嵌入模型时最有效的手段。多跳关系检索不到时，Agent 可以用 `qq_memory_links` 顺着关系手动找。

## 唤醒时带什么

`contextFor` 用最近的消息作查询，再带上当前发言人的关键事实，总字数受 `contextBudget` 限制。只看当前会话和 `global`。控制台「插件 → 仿真与人格 → 提示词预览」能看到每条记忆被取出的原因。

## 遗忘

使用 FSRS 的幂函数曲线：`R = (1 + 19/81 · t/S)^-0.5`，`S` 是保持率降到 90% 的天数。遗忘只影响排序和归档：事实、偏好、关系不会自动归档，事件、待办、笔记的保持率低于 `archiveBelow` 才归档。只有 Agent 主动回忆到的记忆才算强化，唤醒时自动带上的不算。

## 语义检索（可选）

在插件配置里填任意 OpenAI 兼容的 embeddings 接口，比如本地 Ollama 的 `bge-m3`，或硅基流动等云服务。向量在后台补齐；更换模型后已有记忆会重新计算，不同模型的向量不会混用。没配置时其他通道照常工作。

> 目前的语义检索只用模拟接口测过链路，**没有用真实模型测过效果**，下面的成绩不包含它。

## 后台提炼（可选，默认关闭）

Agent 潜水时看到的内容默认不会被记下来。在「插件 → 仿真与人格 → 配置」开启后台提炼后，累计够一定消息数或到定时时间，会跑一轮 AI 从聊天里提炼记忆。这一轮发消息的工具在代码层面被禁用，费用计入「用量」。

## 关联网络

在「插件 → 记忆 → 关联网络」里，记忆和实体（人物、话题）是节点，边来自 `subject`、双链、提到的人名和标签。它不只是展示，也是维护入口：点节点看反向链接；合并重复实体、加别名、标记替代、归档；排查某条记忆为什么和某人连在一起。

## 效果评测

`npm run eval:memory` 输出下面的结果，加 `--fails` 能看到未通过的用例。

- **开发集**：59 条记忆、40 个查询、12 个唤醒场景，实现时参考过，分数偏乐观。
- **留出集**：21 条记忆、24 个查询、5 个唤醒场景，实现完成后才编写，只跑了一次，没有据此调参。

| 指标（留出集） | 旧版 | 旧版关遗忘 | 新版 | 新版 + Agent 多路查询 |
|---|---|---|---|---|
| Recall@5 | 26% | 42% | 68% | 89% |
| 同义 | 0/4 | 0/4 | 0/4 | 4/4 |
| 多跳 | 0/3 | 0/3 | 1/3 | 1/3 |
| 更新 | 1/2 | 1/2 | 2/2 | 2/2 |
| 唤醒命中 | 40% | 60% | 80% | 80% |
| 唤醒违规（带上私聊或过期内容） | 2 | 2 | 0 | 0 |

| 指标（开发集） | 旧版 | 旧版关遗忘 | 新版 | 新版 + Agent 多路查询 |
|---|---|---|---|---|
| Recall@5 | 25% | 63% | 84% | 100% |
| 过期事实比例 | 0%（被遗忘藏起来了） | 75% | 0% | 0% |
| 噪音误报 | 0% | 25% | 0% | 0% |
| 唤醒命中 | 33% | 83% | 100% | 100% |
| 唤醒违规 | 4 | 4 | 0 | 0 |

从消融对比能看出各项功能的实际贡献：

- **事实替代**：过期事实比例从 100% 降到 0%，贡献最明确。
- **人物通道**：两个集合的 Recall@5 都提高 12～16 个百分点。
- **图扩散**：收益有限。多答对 1 题，但开发集 MRR 从 0.69 降到 0.64，留出集多跳也只有 1/3。
- **遗忘曲线**：开发集上开关成绩相同，留出集上关闭反而略好（74% 对 68%）。它的价值是控制记忆规模，不是提高检索成绩。
- **Agent 多路查询**：同义题基本全靠它，且不需要嵌入模型。

### 局限

- 两个评测集都是人工编写的样例，规模小，只能说明相对改进，不代表真实群聊的效果。
- 多跳检索在留出集上明显弱于开发集，有过拟合。「表哥」和「表弟」这类反向关系目前取不到。
- 评测只衡量检索，没有衡量 AI 最终回答的质量。
